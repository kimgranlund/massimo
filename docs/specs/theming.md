# Theming

The inputs a theme sets (root parameters, saved themes, per-element attributes) and how the kit reaches an app: the Panda preset, its conditions and the Panda configs. What each parameter drives: [geometry](geometry.md), [typography](typography.md), [motion](motion.md); colors are Spectrum settings, not theme parameters ([color](color.md)).

## Theme parameters

Numbers the geometry and motion derive from (`tokens/themes/params.ts`; motion: [motion](motion.md#theme-inputs)), emitted as `--ui-<name>` on `:root`:

| Parameter | Range | Default |
|---|---|---|
| `unit` | 2–12 px (0.25 steps) | 4.5 |
| `border` | 0–2 px (whole) | 0 (surfaces separate by fill; invalid controls get a critical-tinted fill) |
| `radius-scale` | 0–3 | 1 |
| `density` | 0, 1, 2 (compact, default, loose; [geometry](geometry.md#density)) | 1 |
| `container-ratio` | 0.3–0.9 (0.05 steps; a ui-container holding containers gives them its radius × k; [geometry](geometry.md#nesting-ui-container)) | 0.6 |
| `radius-group`, `radius-collection`, `radius-card` | 0–1 (0.05 steps; the magnitude t of each family's concentric radius: 1 concentric, 0 square) | 1 |
| `shadow-strength`, `surface-contrast`, `shadow-raised`, `shadow-floating`, `shadow-modal`, `card-raised` | see [elevation](elevation.md#parameters) | 1, 1, 2dp, 8dp, 24dp, 0 |
| `corner-shape` | −1–4 (`superellipse(k)`: 1 round, 2 squircle, 0 bevel, <0 scoop) | 1 |
| `type-ratio` | 1–1.5 | 1.333 |
| `type-rhythm` | 0, 0.5, 1 (× u) | 1 |
| `motion-scale` | 0–2 (× every duration; 0 instant) | 1 |
| `motion-bounce` | 0–1 (× every spring's bounce: 0 critically damped, 1 as designed) | 1 |
| `spring-<spring>-duration` | 0.05–1.5 s (perceptual duration of `quick`, `smooth`, `snappy`, `bouncy`) | 0.2, 0.35, 0.3, 0.45 |
| `spring-<spring>-bounce` | 0–0.6 (0 critically damped) | 0, 0, 0.15, 0.3 |
| `intent-<intent>` | 0–3, whole (the spring `feedback`, `toggle`, `reveal`, `emphasis` runs: 0 quick, 1 smooth, 2 snappy, 3 bouncy) | 0, 2, 1, 3 |
| `pad-<level>`, `gap-<level>` | container padding and gap in u, 0.5 steps (composite padding 0–1.5, others 0–12) | composite 0.5, group 1, collection 2, card-xs 2, card-sm 3, card-md 4, card-lg 5, card-xl 6, panel 6, region 8, page 8 |

## Theme object

A theme is one object (`Theme`, `tokens/themes/theme.ts`; JSON Schema `contracts/theme.schema.json`, generated by `npm run theme:schema`) holding overrides of the kit defaults. Schema version 2 splits it into the four domain parts a brand hydrates ([brand schema plan](../planning/brand-schema.md)); every section is optional:

| Section | Holds |
|---|---|
| `geometry` | `parameters`: unit, density, border, curvature, container radius and nesting ratio, the container ladder, elevation |
| `typography` | `parameters` (`type-ratio`, `type-rhythm`); `sources`: web face stylesheets ([typography](typography.md#face-catalogue)); `faces`: face → font stack; `voices`: voice → face; `colors`: type role → text color |
| `color` | `parameters` (`emphasis`); `spectrum`: Spectrum settings; `roles`: role → requested family; `endpoints`: the neutral step white and black take, or `pure`; `anchors`: exact brand colors per role ([color](color.md#anchors)) |
| `motion` | `parameters`: the multipliers, springs and intents |
| `icons`, `scheme` | the icon set; the preferred scheme (auto, light, dark) |
| `character` | one value per descriptor scale (below) |
| `intent`, `provenance` | reserved for the brand layer; who set a value and why |

Each parameter's part is its `domain` in `PARAMS` (`domainParams(domain)`); a parameter in the wrong part is an error. `themeParameters(theme)` flattens the parts for the resolvers and CSS, and `partsFromParameters(p)` writes them back. `schemaVersion` (2) and `name` (kebab-case) are required. `validateThemeObject(theme)` checks every section against the same exports the schema is generated from and returns every problem at once; font stacks admit family names and commas only, so a theme cannot inject CSS. Version 1 (one flat `parameters` section) loads through `loadTheme`, which runs `migrateTheme` first: each parameter moves to its part, and an unknown one stays where validation reports it.

Each part has a domain manifest (`contracts/domains/<domain>.json`, schema `contracts/domain-manifest.schema.json`): the concepts it covers, the parameter groups and constraints it owns, its specs, resolvers and checks, and a verification record (`contracts/domains/verification/<domain>.verification.json`, `npm run verification -- run domain:<domain>`). Tests keep the manifests a partition of the groups, concepts and constraints, and in step with `PARAMS` and the theme schema.

Saved themes live in `tokens/themes/themes.json` as theme objects keyed by their name, emitted as `:root[data-ui-theme="name"]` (`themeCss`): the parameters as `--ui-*`, faces as `--fonts-<face>`, voices as `--font-voice-<voice>` (serif headings at 400), and, when the theme sets colors, its Spectrum ramps and roles generated at build time, light on the theme root, with `.light` / `.dark` on the root and the OS dark scheme. Themes apply at the document root only, because tokens resolve where they are declared; scope anything else with an explicit element, as the jig does. The jig's **Copy** emits this object and **Load** applies one, version 1 included ([studio](studio.md)).

### Character

A character names a theme in closed words: one value per **descriptor scale**. The scales are data in the domain manifests (`descriptors` in `contracts/domains/<domain>.json`); each names the inputs it sets (a parameter, `spectrum.<field>`, `scheme` or `icons`) and the exact values per scale value, and the scale's `default` value is the kit default.

| Domain | Scales (default first in bold) |
|---|---|
| geometry | scale: xs, sm, **md**, lg, xl · density: compact, **default**, loose · space: tight, **balanced**, airy · curvature: square, crisp, **soft**, round, pill · corner: bevel, **round**, squircle · line: **borderless**, hairline, outlined · elevation: flat, **layered**, floating |
| typography | type-scale: flat, gentle, **classic**, dramatic · iconography: **phosphor**, lucide, tabler |
| color | vibrancy: muted, natural, **vivid** · harmony: **unique**, analogous, complementary, split, triadic · neutral: true, subtle, **tinted**, strong · adaptivity: **both**, light-first, dark-first · emphasis: quiet, **balanced**, loud |
| motion | movement: still, calm, **lively**, playful |

`themeFromCharacter(character, theme?)` (`tokens/themes/descriptors.ts`) sets each named value's inputs into the theme parts; values already in `theme` (hand edits) win; provenance records every input a descriptor set (`{ source: 'character', reason: 'curvature.soft' }`); an unknown scale or value comes back in `unresolved` rather than being guessed. `describeTheme(theme)` reads any theme back to the nearest value per scale with a distance in 0..1 (per input |a − b| / range, or 0/1 for a choice, averaged), so a hand-tuned theme can be summarized or compared. Tests hold the round trip: every value resolves to a valid, lint-clean theme and reads back as itself at distance 0, the scales set disjoint inputs, and the defaults read as defaults. The registry has `descriptor:<scale>` and `descriptor:<scale>.<value>` nodes.

### Lint

Values in range can still break the design together. `contracts/theme-constraints.json` lists the coherence rules, each with a concept, a severity (warning: it works but loses something, such as contrast or target size; info: confirm it is intended), what it checks, a fix, and a failing and a passing fixture; `lintTheme(theme)` (`tokens/themes/lint.ts`) runs one predicate per rule, warnings first. The lint advises and never blocks a setting, a save or a build. Rules today: the 24px target size at the root, the border compact density can hold, panels and cards and floating surfaces staying visible, a modal shadow, reveal overshoot, feedback within 0.3s, near-pill cards, text step 11 at the engine's APCA threshold (naming the tone settings that changed) and text on the primary and critical solids at Lc 60. `npm run theme:lint -w @massimo/ui-kit` lints the defaults and every saved theme (or a file or saved name) and exits 0 unless `--strict`; the jig shows the findings live under **Checks**.

Every parameter is also a registry node (`parameter:<name>`) with its formula and what it drives in `contracts/parameters.json` ([system](system.md#the-system-as-a-function)).

## Brand

A brand is authored first and hydrates a theme (`tokens/brand/index.ts`; JSON Schema `contracts/brand.schema.json`, generated by `npm run brand:schema`; [plan](../planning/brand-schema.md)). It lives beside the theme as its own file, so one brand can hydrate several themes.

| Section | Holds |
|---|---|
| `subject` (required) | name, audience, primary job, kind (product, editorial, tool, campaign, institution), sources of visual character |
| `grounding` | the heritage or movement the brand stands in: a catalogue `ref` (or a free `name`, which comes back as a question), its `relation` (inherit, reinterpret, react-against), principles; an optional secondary |
| `territories` | 1–3 bounded visual worlds (one primary): description, materials, palette, light, textures, composition, type, motion, imagery, `outOfBounds` (`<scale>.<value>`), an optional catalogue `ref` and `character` |
| `muse` | the person, work, object, place or archetype the brand answers to: what to `take` (a quality) and what to `leave` |
| `color` | `anchors` (named exact colors per role), `feedback` (independent or anchored), `character` (vibrancy, harmony, neutral) |
| `type` | `faces` (display, body, utility: a face catalogue `ref` or a family, descriptor, source, weights), `character` (type-scale) |
| `form`, `movement`, `adaptivity` | descriptor values (scale, density, space, curvature, corner, line, elevation; movement; adaptivity) |
| `voice`, `iconography`, `signature`, `avoid`, `rationale` | tone words and microcopy samples; icon set and weight; the one scale the brand pushes and why; anti-choices (`<scale>.<value>`); one line per choice keyed by its brand path |

The catalogue (`contracts/brand-catalogue.json`) holds 14 groundings and 12 territory archetypes:

- Groundings: Swiss International, Bauhaus, De Stijl, Constructivism, Art Deco, Art Nouveau, Arts and Crafts, Ulm School, Memphis, Brutalism, Scandinavian functionalism, Californian modernism, mingei, wabi-sabi.
- Territories: harbor, workshop, botanical, nocturne, archive, laboratory, desert, print shop, alpine, market, atelier, observatory.

Each entry has a canon of descriptor values, its clichés and sources. A grounding also pairs catalogue faces per role (`pairings`: display, body, utility), and hydrate fills a face the brand leaves out from the first pairing (unless the brand reacts against the grounding). Every entry appears in the registry as `grounding:<id>` and `territory:<id>`, with `implies` edges to its descriptor values.

`hydrate(brand)` gives a schema v2 theme and its open questions. The character is resolved in order, each source above the last: the grounding's canon (unless the brand reacts against it), then the primary territory's canon and character, then the explicit `color`, `type`, `form`, `movement` and `adaptivity` choices. `themeFromCharacter` then sets the parameters; anchors become `color.anchors`; faces become font stacks with a fallback per descriptor, a Google face from the catalogue adds its stylesheet to `typography.sources`, and voices point at them; the icon set carries over. Every value's provenance is `{ source: 'brand', reason: '<brand path> → <scale.value>' }`. Anything hydrate cannot decide (a free grounding name, no anchors, no body face) comes back in `unresolved`, never guessed.

`lintBrand(brand)` is advisory, like the theme lint. It checks:

- the frame: grounding, territory and muse are present;
- a rationale for each explicit choice;
- a signature that leaves its default;
- the primary territory's out-of-bounds values and the brand's own avoid list;
- a muse taken as a copy;
- a critical anchor within 30° of the primary's hue;
- each face against the [face catalogue](typography.md#face-catalogue): unknown, missing a weight its voices need, or a different descriptor;
- the generated-looking defaults, as predicates over saturated accent anchors: warm cream with a serif and terracotta, near-black with one acid accent, purple to blue, pill curvature with floating elevation.

`npm run brand -- validate|lint|hydrate <brand.json>` runs them from the command line. Three worked brands (Fjord Ledger, Kiln & Cup, Night Signal), each with a different grounding, live in `tokens/brand/examples/` with the briefs they came from. All three hydrate into valid, lint-clean themes that differ in at least five scales from one another (`test/brand.test.ts`). The briefs double as a reproduction check, so specs and guides do not restate the worked brands' choices.

`themeScopeCss(theme, selector)` applies a theme to one element and its subtree (see Scoped themes below).

## Scoped themes

`themeScopeCss(theme, selector = scopeSelector(theme.name))` (`tokens/themes/scope.ts`) gives the CSS that applies a theme to one element and its subtree (`data-ui-scope="<name>"`), beside other themes on the same page. Tokens resolve their `var()` references where they are declared (`:root`), so the scope redeclares every token that reads a theme input:

- the theme's own variables (`themeVars`);
- the u-based lengths (`unitTokenVars`), the motion tokens and the elevation tokens;
- the shadow layer colors;
- its ramps and roles per scheme;
- `color` and the body voice's `font-family`, so plain text follows the scope.

A theme with scheme `auto` follows the document (`.light` / `.dark` on `<html>`, else the OS). With `light` or `dark`, that scheme is the scope's own default. `.light` / `.dark` on the scope element force one either way. A scope redeclares only what the theme needs: the ramp families its roles use, the length and font-size tokens when it sets geometry or typography parameters, the motion tokens when it sets motion parameters, and the elevation tokens when it sets geometry or colors. A scope with colors and geometry is about 50 KB; one that also sets motion is about 115 KB, most of it motion easings. `themeRootCss(theme)` gives the same theme for the whole document, loaded after the kit CSS. `buildBrand(brand, { scope? })` (`npm run brand -- build`) writes a brand's root or scoped CSS, its font links and its hydrated theme for an app. `apps/studio/scope-check.html` (in `check:browsers`) checks a scope's lengths, Panda tokens, shadows, anchor color and scheme against the resolvers, and that the outside keeps the defaults. The jig's Brand page renders the worked brands side by side this way.

## Per-element inputs

- `size` / `data-size`: u for a subtree (2, 2.25, 2.5, 2.75, 3, 3.5, 4, 4.5, then 0.5 steps to 12).
- `icon-size` / `data-icon-size`: sm, md, lg, fill.
- `density` / `data-density`: compact, default, loose for a subtree, inherited ([geometry](geometry.md#density)).
- `gap`: container gap override in units of u (0–8, 0.5 steps), that element only.
- `radius` (ui-container, presets group, collection and card): the radius magnitude t, 0–1 in 0.05 steps, that element only ([geometry](geometry.md#containers)).
- `.light` / `.dark`: force a color scheme for a subtree.
- `data-font-<voice>="<face>"`: repoint a font voice (display, heading, body, ui, numeric, code) to a face (sans, serif, mono, display); `data-numeric` for figures in the numeric voice, tabular lining when bare, with space-separated variants (`proportional`, `oldstyle`, `fraction`, …) and `data-position="super|sub"` ([typography](typography.md#numerals)).
- `data-type="<role>"`: apply a type role.

## Preset

`preset.ts` merges the theme parameters, reset, scheme rules, geometry, defaults, the container tag rules and FOUC guard per selector (`mergeGlobalCss`; a test fails if any rule is lost), and registers the component slot recipes (`theme.slotRecipes`) and the state conditions. An app that renders the web components sets `staticCss: { recipes: '*' }` and leaves class names unhashed ([components](components.md#styles)). Apps add `@pandacss/preset-base` and the ui-kit preset to their own Panda config. Panda 2 ships no utilities or breakpoints without preset-base and the kit's breakpoints.

Conditions: `osDark`, `dark`, `light` (schemes), plus the state conditions in `styles/conditions.ts`: `keyboard` (keyboard modality) and one condition per data-* state attribute (Base UI names: `checked`, `unchecked`, `indeterminate`, `disabled`, `enabled`, `readOnly`, `required`, `invalid`, `valid`, `dirty`, `touched`, `filled`, `focused`, `busy`, `pressed`, `popupOpen`, `open`, `closed`, `highlighted`, `selected`, `dragging`, `complete`, `progressing`). Both renderers set the same attributes on the same hosts ([state attributes](components.md#state-attributes)), so one `css()` or recipe rule serves both; Panda's built-in clauses for these names (`:checked`, `[aria-checked]`, …) are replaced. Only `disabled` / `enabled` keep a native clause (`:disabled`, for a control disabled by a `<fieldset>`); `enabled` also excludes `data-busy`. `contracts/tokens.json` lists them; a test fails when a condition is uncovered.

A theme scope below the root (the jig canvas) that sets `--ui-unit`, a ladder parameter or a motion parameter also redeclares the dependent Panda tokens there: `unitTokenCss()` ([geometry](geometry.md#panda-tokens-in-u)) and `motionTokenCss()` ([motion](motion.md#theme-inputs)).

## Panda configs

The kit (`packages/ui-kit/panda.config.ts`) and the studio (`apps/studio/panda.config.ts`) set `strictTokens` and `strictPropertyValues`: a value that is not a token is a type error, and a deliberate one-off uses Panda's escape hatch (`'[80rem]'`), which keeps exceptions visible and greppable. Class names are not hashed: the web components put the kit's recipe class names on their parts, so an app that renders them uses `hash: false` and `staticCss: { recipes: '*' }`. Token variables stay readable because the kit and the jig set them by name.
